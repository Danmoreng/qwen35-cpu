# Native Q4_0 comparison — September 6, 2026

## Fixed-work performance

Ryzen 9 9955HX3D, Windows, eight threads pinned to the eight physical cores of
the VCache CCD (affinity `0x5555` / `21845`), CPU-only. Median of three measured
runs after one warmup, alternating case order. No concurrent benchmarks or
quality evaluations. Both engines use the exact same pure-Q4_0 GGUF file.

| Engine / checkpoint | Prefill P512 | Prefill P4096 | Decode P512/N128 |
| --- | ---: | ---: | ---: |
| This engine, H128/Q4 | 2,132.99 | 1,855.13 | 120.25 |
| **This engine, Q4_0 `--pure`** | **2,037.11** | **1,771.58** | **120.47** |
| llama.cpp, Q4_0 `--pure` | 1,042.64 | 972.92 | 100.16 |

All throughput values are tokens/s. Prefill uses the forward-only timing field,
consistent with the original comparison; raw profiles also retain wall time
including request initialization. The earlier conversational status numbers
used that wall time. Native Q4_0 has about 4.5% lower prefill
throughput and practically equal decode throughput relative to H128 in these
new runs. Against llama.cpp with identical weights it delivers **1.82–1.95x
prefill and 1.20x decode throughput**. This is an engine comparison, not a claim
that the Q4_0 quantization itself is faster on every CPU.

P512 uses 128 fixed output tokens; P4096 uses two. Prefill includes the final
full-vocabulary head and excludes allocation/model loading. Decode counts the
127 subsequent forwards, not the first output token produced by prefill. Full
logits are computed in both engines; no greedy-head shortcuts, shared prefixes
or early EOS exits. FP16 KV caches. Native prefill chunks are 128 tokens;
llama.cpp uses n_batch=2048, n_ubatch=512 and flash attention. llama.cpp revision
`73a43d1f69345aee8bb186ef4b3172cef892f2e5`, same CPU-only AVX-512/VNNI build as
the [original comparison](comparison-2026-09-06.md).

The earlier README H128 measurements are retained as historical results. Do
not combine their different run times with these new paired measurements to
compute speedups. Multi-request performance was not remeasured in this bounded
follow-up; multi-request correctness was tested.

## Quality: distinguish checkpoint and execution differences

The original 8,192-position evaluation of this exact pure checkpoint in
llama.cpp measured KL(BF16 || Q4_0-pure) **0.144522** and perplexity **18.025885**.
The mixed file called Q4_0 measured 0.068388 / 15.580883, and H128 measured
0.174841 / 18.583290 in this engine. The mixed file uses higher precision for
some tensors and a different calibration recipe. See the [original quality
table](results/2026-09-06/quality-summary.csv); those are not new native-Q4 scores.

A **bounded native compatibility check**, using the original first WikiText-2
window (256 shared prompt IDs, 512 teacher-forced target IDs), measures:

- KL(llama.cpp Q4_0-pure || native Q4_0-pure): **0.00085611**.
- KL(BF16 || native Q4_0-pure): **0.11773757**, perplexity **8.914091**.

The latter two numbers describe only that one window and must not be compared
to the 8,192-position averages above. There is no complete new native Q4_0
quality sweep in this change. The low same-checkpoint KL and kernel/model tests
support numerical compatibility, not bit-identical execution or task quality.

The previously selected German arithmetic regression still fails: both engines
choose **2** for the answer in “Was ist 2 + 2? Antworte nur mit der Zahl.” after
the expected four-token think wrapper. Native margin logit(4)-logit(2), after
the historical repetition penalty, is **-1.02330**. Native versus llama.cpp KL
on these five positions is **0.00113140**. This checkpoint limitation is not
fixed by removing H128. This selected example is separate from corpus metrics.

## Reproduce and inspect

Build/setup and fixed-token generation are described in the original comparison.
Use the archived matrix arguments with `scripts/benchmark-inference-seq.ps1`:

```powershell
./scripts/benchmark-inference-seq.ps1 -Matrix benchmarks/native-q4_0-2026-09-06/quick-matrix.json -OutputDir benchmarks/native-q4_0-rerun -Runs 3 -WarmupRuns 1 -Affinity 21845
python scripts/evaluate-native-gguf.py --quant Q4_0-pure --windows 1 --out benchmarks/native-q4_0-quality-rerun
python scripts/evaluate-native-gguf.py --quant Q4_0-pure --arithmetic --out benchmarks/native-q4_0-arithmetic-rerun
./build/cpu_scheduler_model_test.exe models/hf-download-test models/llama-comparison/Qwen3.5-0.8B-Q4_0-pure.gguf
```
