# Closing the Linux prefill gap to ik_llama.cpp

The native H128 engine now uses a wider DOT4 matrix kernel for AVX-512/VNNI
prefill. A fresh paired Linux/Ryzen series measures **25.8% faster P512 prefill
and 28.6% faster P4096 prefill**, with effectively unchanged single-request and
batch-16 decode. The checkpoint, quantization, activation transform and storage
layout are unchanged. The new code is isolated in
`src/cpu/q4_dot4_prefill_avx512.cpp` behind the existing runtime ISA dispatch.

## Why IK was faster

The earlier comparison needs two distinctions. IK's pure Q4_0 prefill was
substantially faster than native H128, but its IQ4_K_R4 and IQ4_KS_R4 prefill
was already slower than native H128. Those formats do not use the same kernels
or have equivalent quality. Their decode ranking is not a prefill ranking.

Decode handles one new token per request, whereas prefill can reuse weights
across many tokens. This gives matrix tiling and SIMD arithmetic much more
influence on prefill throughput. A smaller quantized file can help decode, but
file size alone does not establish why one format is faster: the kernels and
in-memory representation also differ.

The source comparison found a concrete opportunity:

- The old native AVX-512/VNNI DOT4 path used **256-bit arithmetic**, with
  eight output rows and sixteen tokens per main tile. EVEX/VNNI support did
  not mean the arithmetic itself was 512 bits wide.
- IK's repacked Q4_0 path pairs eight-row blocks into **512-bit lanes** and
  reuses unpacked weights across tokens. Its implementation also has its own
  activation packing, tile selection and memory layout.
- Native profiling placed 155.47 ms of a 236.26 ms P512 prefill in the Q4
  matrix-kernel calls, versus only 8.28 ms in H128 activation preparation.
  The Hadamard transform was therefore not the main bottleneck.

Primary source references are the pinned IK
[matrix tiling implementation](https://github.com/ikawrakow/ik_llama.cpp/blob/fe215a8ccdce6b844d2a3a3bbde08ae76a6284bf/ggml/src/iqk/iqk_mul_mat.cpp)
and [Q4_0_R8 kernel](https://github.com/ikawrakow/ik_llama.cpp/blob/fe215a8ccdce6b844d2a3a3bbde08ae76a6284bf/ggml/src/iqk/iqk_gemm_legacy_quants.cpp#L1111).
Our implementation widens the existing native DOT4 arithmetic; it does not
import IK's runtime, change the checkpoint, or add a backend dependency.

## Implemented change

Two adjacent existing eight-row blocks occupy the lower and upper halves of
a 512-bit vector. Each tile computes **sixteen output rows for eight tokens**.
Unpacking and weight scales are reused, while eight accumulators limit register
pressure. A sixteen-token version was also measured but provided no improvement,
so it was not retained.

The new path is selected only for AVX-512/VNNI batches of at least 32 tokens.
Single-token decode and short batches retain the existing implementation. Row
and token tails fall back to the established kernel. AVX2, AVX-VNNI and scalar
dispatch remain intact. No wider packed-weight copy is allocated.

The per-block integer correction, scale multiplication and floating-point FMA
order for each output are preserved. This is an implementation optimization,
not a new quantization or a change to accumulation accuracy.

## Matched performance

Arch Linux, Ryzen 9 9955HX3D, GCC 16.2.1 Release, eight physical V-Cache cores
0–7 (`0xff`), maximum-performance power policy. Codex is automatically minimized
and XFCE compositing disabled for each complete series; the display remains
2560×1600 / 240 Hz. The wrapper restores the initial compositor/window state.

All final candidates run sequentially through
`scripts/benchmark-inference-seq.ps1`, with one warmup and three measured runs,
alternating case order. The same fixed tokens, FP16 KV, full-vocabulary logits
and 16,384-token context limit apply. There is no concurrent compilation or
quality scoring. Loading, repacking, tokenization and HTTP are excluded. Native
prefill retains its default 128-token chunks; IK retains `n_ubatch=512` and
runtime repacking. These are implementation choices, not changes to input work.

| Native H128, optimized | **2,751.34** | **2,481.04** | **127.76** | **640.21** |
| IK pure Q4_0 | 2,893.11 | 2,537.27 | 126.79 | — |

Values are median tokens/s from this fresh series, not mixed with earlier
sessions. P512/N128 counts 127 decode forwards per request; P4096/N2 supplies

The new kernel removes about 80–91% of the measured prefill throughput gap to
IK pure Q4_0. IK still leads by 5.2% at P512 and 2.3% at P4096 relative to
the optimized native result. Native decode changes by +0.05% at B1 and -0.27%
at B16, which does not indicate a meaningful regression in this experiment.
Windows and the Intel/AVX2 platform were not rebenchmarked; earlier tables are
historical measurements of the original native build.

## Profiling and validation

Separate instrumented series isolate the affected work. P512 Q4 kernel time
drops from 155.47 to 105.16 ms; P4096 from 1,267.99 to 776.21 ms. Preparation
remains approximately 8.3 and 66 ms respectively. These are medians of separate
diagnostic series, not precision paired per-stage speed claims. Instrumented
timings are excluded from the performance table. See the
[operation profile](results/prefill-avx512-2026-09-07/operation-profile.csv).

All 16 CTest tests pass. The expanded DOT4 test covers available scalar and SIMD
backends, extreme signed activations, positive/negative/zero scales, row tails,
token tails and padded output strides, comparing results bitwise on this host.

Full-model validation compares both CLI builds on the 16 existing English test
windows plus prompt lengths 31, 127, 128, 129, 511, 512, 513 and 4,096. Sixteen
forced output positions per prompt yield **95,354,880 full-vocabulary logits**
over 384 positions. Every candidate dump matches its baseline byte for byte;
finite-value and record-count checks pass. This validates implementation
equivalence on these cases, not universal correctness for every possible input.
No quality score was refitted or replaced. See
[equivalence hashes](results/prefill-avx512-2026-09-07/equivalence.csv).

## Evidence and remaining work

The [manifest](results/prefill-avx512-2026-09-07/manifest.json) preserves source,
binary and checkpoint hashes, build flags, commands, affinity, upstream revision
and desktop snapshots. Raw profiles, screen trials, matrices, logit identities,
build/test logs and the wrapper remain in ignored
`benchmarks/prefill-ik-investigation-20260907/`. Models, binaries and raw ZIPs
are not committed. Build with `cmake -S . -B build-prefill -G Ninja
-DCMAKE_BUILD_TYPE=Release`, then `cmake --build build-prefill -j 8` and
`ctest --test-dir build-prefill --output-on-failure`.

The remaining prefill time includes attention, normalization, activation work,
execution overhead and the vocabulary head. IK's different prefill chunking
and attention kernels are further candidates for investigation; their individual
contributions to the remaining gap have not been isolated. This change does not
claim that simply doubling SIMD width always doubles application throughput.
