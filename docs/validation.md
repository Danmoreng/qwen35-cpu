# Validation

Run checks from the repository root. Test sources and fixtures live in `tests/`;
model weights, generated browser bundles and benchmark outputs are local inputs.

## Native build and unit tests

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
```

On Windows, use `scripts/build.ps1` followed by the same CTest command.
The default server build registers 18 C++ tests. If Python and NumPy are
available at configure time, CTest also registers `evaluation_scripts` and
`calibration_basis`. Use `ctest --test-dir build -N` to inspect the actual set.

Coverage includes Q4/DOT4/H128/Q8 and K-quant kernels, tiled attention,
DeltaNet, artifact/GGUF readers, mixed-precision and head execution, KV pages,
and the System One protocol. Q8 and head tests exercise retained runtime and
packer features, including options used by decision calibration; they are not
disposable benchmark output. The GGML-derived K-quant fixtures have their own
[provenance](../tests/fixtures/k-quants/README.md).

## Browser contracts without model downloads

```sh
node tests/demo_scenarios_test.mjs
node tests/model_manifest_test.mjs
node tests/wasm_capabilities_test.mjs
node tests/wasm_logit_parity_test.mjs
```

These check demo rules, model manifests, the fused-FMA capability guard and
bitwise-logit comparison logic. They do not replace inference in a real browser.

## Model-backed checks

The normal native build also produces `cpu_scheduler_model_test`,
`cpu_prefix_model_test`, `cpu_batch_model_test` and `cpu_prefill_chunk_model_test`.
They require matching model config/tokenizer files and a packed checkpoint.
For model-backed checks:

```sh
./build/cpu_scheduler_model_test models/qwen3.5-0.8b models/qwen3.5-0.8b/model.q35h --pages
./build/cpu_prefill_chunk_model_test models/qwen3.5-0.8b models/qwen3.5-0.8b/model.q35h
./build/cpu_prefill_chunk_model_test models/qwen3.5-0.8b models/qwen3.5-0.8b/model.q35h --pages
python tests/server_smoke.py --help
python tests/systemone_readout_parity.py --help
python tests/server_api_test.py --help
```

The prefill-chunk model check requires the same optional model files. It compares
full-vocabulary logits at chunk 128 against chunks 512/1024, including registered
prefixes ending before and after the initial attention boundary. Run it with and
without shared FP16 KV pages. The qev AVX2 tuning study uses the pinned public
qev model; see [the report](benchmarks/qev-avx2-cloud.md).

`server_smoke.py` covers completion validation, concurrency and prefix behavior.
`server_api_test.py` compares chat requests against raw completion using pinned
Qwen template fixtures, including Unicode and multi-turn history. `--sdk` also
checks the official OpenAI and Anthropic Python clients, including streaming,
Messages token counts, stop identity, cache accounting and typed errors; install dependencies with
`python -m pip install -r tests/requirements-server-sdk.txt`. The dependency-free
C++ protocol test consumes golden prompts generated by the model's actual Jinja
template. Regeneration uses `tests/generate_chat_fixtures.py` and optional Jinja2;
neither package is needed by the native server.
Streaming checks cover JSON/SSE output and usage parity, hidden stop sequences,
disconnect recovery and pre-stream validation errors. Host tests cover every
byte split of a Unicode/stop fixture, partial UTF-8, overlapping stops and bounded
event queues with a separate terminal lane. The scheduler model test verifies
that generated-token accounting includes stop tokens withheld from output.
Structured-output tests cover JSON syntax, UTF-8 and surrogate escapes, schema
requirements/bounds, invalid keywords, EOS masking and all-masked failures.
Real-model checks exercise greedy and sampled schema output, JSON/SSE parity,
required/named tool choice, SDK argument deltas, tool-result history and truncated
calls through both APIs. The scheduler verifies constraint acceptance on single
and batched greedy paths with independent per-request state.
Automatic-cache checks cover cold/warm response parity, cache-key isolation,
concurrent single-flight reuse and growing chat history. Model scheduler tests
compare full-vocabulary logits while extending a cached prefix, check longest
exact matches and namespace separation, and force LRU eviction under a small
budget. Decision HTTP checks can compare against `--reference-server` to verify
answers and usage against an uncached prior build.
`systemone_readout_parity.py` compares full and selected decision readouts and
chunk sizes over HTTP. `systemone_server_smoke.py` and
`systemone_tokenizer_parity.py` additionally accept prepared protocol/reference
inputs; see their `--help` before running them.

`calibration_packer_model_test.py` requires explicit `--packer`, `--model-dir`
and `--calibration` inputs. It verifies malformed offline calibration data is
rejected without leaving output artifacts.

For WASM kernel, quantizer, UI and full-model parity checks, follow the
[browser build guide](browser/build.md). Native browser-reference and
selected-logit model targets are enabled with `-DQWEN35_BUILD_WASM=ON`.
Browser integration scripts require a local served bundle, model and Playwright;
they are deliberately separate from the dependency-free Node contract tests.

## CI and release checks

The [workflow](../.github/workflows/build-release.yml) builds on Windows/MSVC
and Ubuntu/GCC, runs CTest and Node contracts, and verifies decision HTTP
readout parity with the pinned public qev model. Base-model scheduler and
extracted-package HTTP checks run when the pinned model variables are configured;
release tags require those variables. See [publication](publishing.md).

Passing correctness checks does not establish a new speed or quality score.
Run timed comparisons separately through `scripts/benchmark-inference-seq.ps1`.

## JevBench decision comparison

`scripts/evaluate-jevbench.py` requires the pinned JevBench checkout
`1bcc55eb6c8cffde2306b3db03ede39b61c6152a` and the checksum-verified public
qev checkpoint. Its default backend uses the native server. The optional
`--backend llama` path requires a CPU `llama-server` build with `/v1/systemone`
support, its source checkout, and the pinned publisher Q8_0 or BF16 GGUF named
by the driver. These inputs are optional and are not downloaded by CTest.
The harness, adapters and scorer remain unmodified; no Python model runtime
is required. The full serial measurement uses the sequential PowerShell runner
with one warmup and three measured passes.

`scripts/summarize-jevbench.py` verifies complete task coverage, raw response
hashes, strict schema validity, repeated predictions/probabilities, token usage
and server shutdown before exporting the comparison. Rendering the English
shareable PNG/SVG with `scripts/plot-jevbench.py` additionally requires
Matplotlib. See [the frozen protocol and results](benchmarks/jevbench-v1.md).

`scripts/audit-jevbench.py` recomputes paired disagreements from those saved
results. Its `--prepare` mode additionally requires `systemone_protocol_test`
and the pinned native qev tokenizer/config to export exact native input tokens.
The quality-only control uses the existing CPU `qev-llama-study` target with
the pinned BF16/Q8 GGUFs; it has no Python inference dependencies and does not
produce latency measurements. Keep one control process at a time and use a
bounded runtime that ends before the daily work cutoff.

Historical extraction and release reports remain in [Git history](history.md).

## NVIDIA When2Call decision comparison

`scripts/when2call.py` uses only the Python standard library. Preparation needs
the exact NVIDIA MCQ test file and the native `systemone_protocol_test` with
the pinned qev tokenizer/config. Evaluation needs the native qev server, the
publisher Q8/BF16 GGUFs and CPU llama.cpp described in the JevBench section.
Optional `--backend vulkan` uses a separate stock build of that same revision
at `.cache/llama-qev-vulkan/bin/llama-server`, with the B70 as `Vulkan0`.
The native engine does not gain a GPU backend. Compare the complete GPU runs
against CPU decisions on the frozen 128-item panel.
Every request must fit its context window; actual token counts, zero generated
tokens and disabled prefix caching are checked. Run performance cases through
`benchmark-inference-seq.ps1` with affinity 63. The driver checks the daily
deadline and terminates its own server on completion or interruption.

`python tests/when2call_test.py` checks answer-key/metadata isolation, preservation
of shuffled candidate texts and category mapping, and scoring of invalid and
unsupported-class predictions, rejection of changed prediction records, and
explicit handling of interrupted prefixes without requiring models. CTest includes it as
`when2call_scripts` whenever Python is available.
`scripts/summarize-when2call.py` independently verifies raw response hashes,
recomputes every prediction and Brier score, checks complete-test and CPU-panel
coverage, records backend agreement, and checks CPU affinity and server shutdown.
See the [When2Call protocol](benchmarks/when2call.md).
