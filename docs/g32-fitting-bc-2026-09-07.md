# G32 fitting experiments B and C

This report covers the initial screen and collector work. The subsequent
[256-document study](g32-large-calibration-2026-09-07.md) contains the completed
larger-corpus comparison, independent final check and matched CPU speed results.

The objective is better PPL and teacher KL while preserving the existing G32
artifact representation and inference kernels. The calibrated four-document
MSE16 artifact remains the default until model-quality evidence supports a change.

## B: data and sampling

The first screen uses 40 sequences of 1,024 tokens (40,960 tokens) per recipe:

| Recipe | German | English prose | Code | Dialog | Math |
|---|---:|---:|---:|---:|---:|
| B-prose | 0% | 100% | 0% | 0% | 0% |
| B-mixture | 25% | 25% | 20% | 20% | 10% |

Sources: FineWeb2 `deu_Latn`, FineWeb-Edu, CodeParrot Clean, SmolTalk
`smol-magpie-ultra`, and OpenWebMath. The user approved a public replacement for
gated The Stack Smol. CodeParrot is a **Python-only screening substitute**;
selection restricts its recorded licenses to MIT, Apache-2.0 and BSD variants.
Dataset revisions, source file paths, record indices, document/source identifiers,
licenses when available, full source hashes and exact token hashes are frozen in
the local corpus manifest. Raw external source texts are not committed.

This is a bounded first-shard screen, not the proposed final 256-sequence corpus.
The 256-sequence expansion, multiple code languages and 4K/8K contexts have not
been run. Document selection is deterministic first-eligible order, not an IID
sample of each corpus. Ten separate documents (two per domain) are reserved for
a 1,280-position final evaluation before any fitting. Selection uses the model's
chat template only for dialog records. Other documents retain their plain form.

The old collector saved the first 256 projection-input rows. The optional new
collector uses a deterministic capacity-256 reservoir over the whole document,
with per-projection seed 1234. It records rows seen as well as rows retained.
This captures later context without writing every activation. Head inputs have
128 available rows per sequence and are all retained. B-prose and B-mixture use
the same sampler; comparisons against the old four-document baseline change both
data and sampling, so they do not isolate corpus size alone.

Selected complete source documents were checked against the reserved final and
existing evaluation sources for normalized paragraph overlap and 32-word spans.
No shared 32-word spans or literal `2 + 2` fixture were found. No source group
crosses calibration/final splits in the selected corpus. These checks reduce
overlap risk; they do not establish the model's pretraining independence.

## C: bounded error compensation

C uses only the original four-document captures and their original diagonal
importance. Full second moments are accumulated **within fixed 128-channel
blocks**, in the actual H128 basis (identity for the tied head). Cross-block
covariance is omitted. This is a limited GPTQ-style experiment, not full-matrix
GPTQ or sequential layer recalibration.

For each block, normalize second moments by mean diagonal energy, add 0.01 times
identity for inversion and form the upper Cholesky factor of the inverse. Fit a
stored FP16 scale for each G32 group, then quantize its columns while compensating
the remaining columns inside the 128-channel block. Finally compare reconstruction
error against the original weighted MSE16 candidate using the undamped second
moments; retain the original whenever the new candidate is not better.

The resulting artifact still uses the same signed 16-level G32 groups, H128 seed,
DOT4 layout and tied head. No extra runtime metadata or expanded weights are
needed. Covariance metadata is an offline-only input and a provenance sidecar.
Conversion uses eight independent row workers; inference code is unchanged.

Tests cover exact retention for diagonal covariance, lower reconstruction error
on correlated synthetic inputs, baseline fallback and singular-factor rejection.
All 16 CTests passed after the initial implementation. Model quality remains an
empirical check; a lower local reconstruction objective is not a PPL guarantee.

## Offline CUDA collection and residency

At the user's explicit request, a separate llama.cpp CUDA calibration tool was
added. CPU inference and its comparison target remain CPU-only. The CUDA teacher
log confirms 25/25 layers offloaded on the RTX 5080 Laptop GPU, with approximately
1,436 MiB of CUDA model storage. The resident tool requires a CUDA device and
loads the teacher once per job list. It clears recurrent/KV state and reservoir
state between documents. Known teacher-forced tokens can be processed in batches.

An A-B-A sequence reproduced A's final logits and all 187 captured projections
bit-for-bit after processing B, in both resident modes. Batched versus sequential
execution is not numerically identical: median projection relative RMS difference
was 0.0026812, maximum 0.0054737; final-logit KL was 0.00006306 with unchanged
top-1. These are collector checks, not a GPU-calibrated checkpoint quality claim.
The B quality results above still use CPU-collected activations.

Whole-process wall-time medians, three measured runs plus one warmup, measured
sequentially with `scripts/benchmark-inference-seq.ps1`:

| Workflow | Documents per process | Median wall time |
|---|---:|---:|
| CPU, fresh process, 1,024 tokens | 1 | 8.902 s |
| CUDA, fresh process, 1,024 tokens | 1 | 8.808 s |
| CUDA resident, sequential teacher, 1,024 tokens/document | 3 | 14.607 s |
| CUDA resident, batched teacher, 1,024 tokens/document | 3 | 5.602 s |
| CPU, fresh process, 4,096 tokens | 1 | 15.615 s |
| CUDA, fresh process, 4,096 tokens | 1 | 7.210 s |

The resident batched result amortizes to 1.867 seconds/document for this three-job
screen. It includes startup and raw capture writes, but excludes subsequent
statistics compaction and checkpoint fitting. Comparing it to fresh CPU processes
measures both residency and GPU batching benefits, not GPU acceleration alone.
Raw profiles, commands, hashes and affinity are retained in the local
`bc-collector-wall-speed` and `bc-resident-speed` directories.

`collect-resident-calibration.py` additionally overlaps CPU statistics compaction
with the next GPU document, retains at most two documents of raw captures, checks
a 16 GiB free-space reserve, and deletes verified raw tensor files after
compaction. Its three-document pilot completed with one model load; all 187
projection importance files were successfully fitted from the compacted output.
This complete pipeline includes additional CPU processing beyond the table above.

For diagonal MSE16, compact sums reproduce all 187 importance files byte-for-byte
in the raw-versus-compacted validation. The 70 B calibration documents' 18.49 GiB
of raw captures were therefore removed after verification. Original four-document
raw captures remain available for covariance experiments: diagonal statistics
cannot reconstruct covariance. Repeated GPU benchmark raw captures are also
removed after recording hashes and numerical validation; profiles are retained.
